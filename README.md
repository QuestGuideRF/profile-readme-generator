# Profile Readme Generator


Это уже готовая статическая версия `Profile Readme Generator`, подготовленная для загрузки на обычный shared/static hosting без `VPS` и без серверного запуска `Node.js`.

## Что делает проект

Для изменения адреса ресурсов API используется [шаблон окружения](.env.example).

`Profile Readme Generator` — это веб-приложение для визуальной сборки `README.md` профиля GitHub. Оно помогает выбрать шаблон, настроить секции, посмотреть результат и получить готовый Markdown без ручной верстки.

## Что загружать на хостинг

На хостинг нужно загрузить всё содержимое этой папки, кроме `README.md`.

То есть нужно отправить:

- папку `_next/`
- папку `api/`
- папку `assets/`
- папки `privacy-policy/` и `result/`
- файлы `.env`, `index.html`, `404.html`, `manifest.json`, `sitemap.xml`, `sw.js`

## Как загрузить, чтобы всё работало

1. Откройте файловый менеджер хостинга или FTP.
2. Перейдите в корень сайта:
   `public_html/`, `www/` или аналогичную папку.
3. Загрузите туда всё содержимое текущей директории, кроме `README.md`.
4. Не загружайте папку целиком внутрь ещё одной папки, если не настраивали отдельный путь.

Правильный результат:

- `index.html` лежит в корне сайта
- `_next/` лежит в корне сайта
- `assets/` лежит в корне сайта
- `api/` лежит в корне сайта

## Важные условия

- Сайт должен открываться из корня домена или поддомена.
- Если загрузить проект в подпапку вроде `https://site.ru/project/`, текущие пути могут не подойти без отдельной пересборки исходников с `basePath`.
- Нельзя пропускать папку `_next/`, иначе не загрузятся стили и JavaScript.
- Нельзя переименовывать файлы после сборки.
- Нельзя загружать только `index.html` без остальных файлов.
- Для автоматического создания SVG на сервере хостинг должен поддерживать `PHP`.
- Папка `assets/` должна быть доступна для записи PHP-скриптам, иначе SVG-карточки нужно будет загрузить вручную из списка файлов результата.

## Серверная генерация SVG

При открытии страницы результата проект создаёт SVG-карточки для выбранного GitHub-пользователя и сохраняет их в `assets/`.

За это отвечают файлы:

- `api/github-contributions.php` — получает календарь вкладов GitHub, чтобы серия активности и график строились по реальным contributions, а не по ограниченной ленте events.
- `api/save-generated-assets.php` — сохраняет готовые SVG-файлы в папку `assets/`.

В файле `.env` укажите домен, с которого GitHub будет загружать картинки:

```env
README_ASSET_HOST=https://your-domain.ru
README_ASSET_PATH=/assets
```

После этого в готовый `README.md` будут вставляться ссылки вида:

```html
<img src="https://your-domain.ru/assets/username-github-stats-green-xxxxxx.svg" alt="Статистика профиля" />
```

## Ошибка со стилями и скриптами

Если в консоли браузера появляются ошибки вида:

```text
Failed to load resource: the server responded with a status of 404 ()
```

для файлов из `/_next/static/...`, это почти всегда означает одно из двух:

1. На хостинг не была загружена папка `_next/`.
2. Проект загружен не в корень сайта, а в подпапку.

В этом пакете папка `_next/` уже присутствует, и локально файлы `css/js` из неё отдаются корректно.

## Основные возможности

- визуальная сборка `README.md` профиля GitHub;
- выбор шаблонов;
- добавление секций с текстом, технологиями, соцсетями, статистикой и активностями;
- предпросмотр результата;
- получение готового Markdown;
- статическая публикация без VPS;
- локальная генерация `trophy`, `stats`, `languages` и `streak` без зависимости от внешних карточек.

## Краткое использование

После загрузки на хостинг откройте сайт в браузере и:

1. выберите шаблон;
2. настройте нужные блоки;
3. заполните данные профиля;
4. проверьте результат;
5. откройте итоговую страницу и скопируйте готовый `README.md`.

### Основы Git

`Git` — система контроля версий, которая хранит историю изменений проекта.

Базовые команды:

```bash
git init
git add .
git commit -m "Начальная версия"
git status
git log
```

### GitHub

`GitHub` нужен для публикации `Git`-репозиториев, совместной работы и оформления портфолио.

Базовые команды:

```bash
git remote -v
git push origin main
git pull origin main
```

### Ветки

Ветки помогают изолировать задачи и не ломать основную версию проекта.

```bash
git branch
git checkout -b feature/new-section
git checkout main
git merge feature/new-section
git branch -d feature/new-section
```

### README профиля GitHub

Сильный профильный `README` обычно включает:

- короткое представление;
- блок «Обо мне»;
- список технологий;
- контакты;
- ключевые проекты;
- аккуратную структуру.

### Портфолио разработчика

Сильное портфолио — это не количество репозиториев, а качество оформления и понятность проектов.

Лучше показать:

- несколько завершённых работ;
- понятный `README`;
- рабочий запуск;
- чистую структуру;
- внимание к деталям.
